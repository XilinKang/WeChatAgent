# 2026-10-27 开发问题复盘：微信连接、设置保存与自动回复

本轮开发基于上游 [sourcepro5/WeChatAgent v0.4.1](https://github.com/sourcepro5/WeChatAgent/releases/tag/v0.4.1)，目标是修复开发环境接入和日常使用中的实际阻断问题。本文不包含真实账号、聊天内容、读取凭据、用户目录或私人插件配置。

## 问题与修复

| 问题 | 表现与根因 | 本轮处理 |
| --- | --- | --- |
| 微信发送组件不可达 | 普通微信与项目匹配客户端不是同一实例，发送端口未监听；选择数据库目录并不能替代启动发送组件 | 核对实际主进程、核心版本和组件健康状态，使用项目匹配客户端完成连接 |
| 自动连接一直等待 | 发送组件正常不等于已取得数据库读取凭据；仅退出账号再登录，可能不会重新触发数据库初始化 | 优先验证并复用已有凭据；没有有效凭据且微信已登录时，立即返回 `READER_LOGIN_RESTART_REQUIRED`，引导完整重开匹配微信 |
| 连接时机依赖人工排序 | 用户可能在读取组件准备好之前完成登录，最后只得到笼统超时 | 新增“重开微信并连接”入口，沿用进程归属核验和停止确认，依次执行重开、连接准备、提示用户登录、验证与保存 |
| 配置保存持续冲突 | 后台更新配置后，旧页面继续提交旧版本；乐观锁正确阻止覆盖，但界面没有提供恢复路径 | 保存遇到版本冲突时，基于原始配置、本页草稿和最新配置进行三方合并，并有限次重试 |
| 刷新不能解决冲突 | 页面有草稿时，原刷新按钮只刷新服务状态，不读取新配置 | 刷新同步最新配置，同时保留本页改动和刷新期间的新输入；同一项被两边修改时逐项选择 |
| 部分成功被报成全部失败 | 好友名单已经保存，后续提交过期连接表单失败，页面却只显示统一错误 | 单独同步连接表单版本；与已验证账号相同且未输入新密钥的旧草稿自动归一化；明确显示其他设置已保存、连接尚未完成 |
| 收到消息却未调用模型 | 实际消息桥接入口的两个设置回调引用未定义变量 `nativeRoot` | 改为已定义的项目目录 `historyRoot`，并补充运行真实桥接入口的回归测试 |
| DSH 提示会话已存在 | 开发目录缺少会话映射，但 DSH 独立保留了相同账号范围的会话；再次创建发生冲突 | 在创建前检查确定的账号范围会话 ID，存在时恢复已有会话，不删除原历史 |
| DSH 接到了旧目录 | 程序位置未配置，已有桥接插件仍链接到旧安装目录 | 修复本机程序位置和插件链接，保留原配置及历史；公开源码使用通用插件入口，不携带这些本机修改 |

## 保存与同步的边界

1. 不同设置项的改动可以自动合并，同一设置项的冲突必须明确选择。
2. 好友、群聊授权名单按完整设置项处理，不静默混合两个窗口的授权增删。
3. 微信账号发生切换时，阻止把旧账号页面的草稿自动应用到新账号。
4. 保存期间新输入的内容保留为下一次草稿，不被保存响应覆盖。
5. 手动输入的读取凭据不会在刷新时被静默丢弃，也不会自动转移到另一账号。
6. 重新连接不会自动完成微信登录；需要重开微信时，先展示核验过的进程并要求用户确认。

详细使用方法见[设置同步与微信重新连接](../CONSOLE_RECOVERY.md)。

## 验证结果

- 真实问题复现：消息成功进入缓存，但未进入模型调用；桥接入口测试复现了未定义变量错误。
- 自动回复修复相关测试：37 项通过；会话恢复相关测试：17 项通过。
- 设计修复后的全量回归：共 521 项，520 项通过、0 项失败、1 项跳过。
- 最后一次保存提示调整后，保存同步与登录顺序的针对性复核：9 项全部通过。
- 已在本机授权账号完成普通文字消息链路验证：读取新消息、调用模型、生成回复，并取得微信服务器发送确认。
- 已验证现有账号直接复用已保存凭据完成连接，无需退出微信或重新获取密钥。
- 双窗口冲突、取消合并、保存期间继续输入、账号切换保护、错误凭据和重开顺序均通过隔离测试；测试使用虚构账号和模拟传输。

上述本机验证不等同于所有媒体格式、群聊模式、第三方插件或其他物理设备均已实测。

## 仍需明确的限制

- 当前发送组件仍要求 Windows x64 微信 **4.1.10.27**，本轮没有新增对 **4.1.15.56** 的适配。
- 本轮是源码开发修复，没有生成或验证新的安装包，也没有增加版本标签；已有 `release-profile.json` 描述的是原上游发行构建，不是这些修复后的新安装器。
- “服务连接正常”只说明基础连接就绪，不能替代对消息接收、请求提交、模型完成和发送回执的逐环节验证。

## 开发经验

### 测试需要覆盖实际入口

只验证单个引擎或工具函数，会遗漏启动入口中回调闭包、路径变量和参数接线错误。新增桥接入口测试使用真实消息处理引擎，替换为模拟模型与传输，验证一条输入能走完决策和回复流程。

### 冲突保护需要完整的恢复交互

保留版本检查，避免后写覆盖先写；同时提供同步、三方合并、显式选择和取消保留草稿的完整流程。提示用户刷新之前，应确保刷新确实能解决版本不同的问题。

### 多阶段操作需要分阶段报告

配置写入成功、凭据验证成功、实时账号核对成功和服务应用成功是不同结果。后一步失败时应明确保留了哪些成果，不能让用户误以为所有修改都没有保存。

### 独立程序的数据生命周期需要独立处理

DSH 的会话和账号数据独立于开发目录。新建开发环境或迁移配置时，应检查已有会话并恢复确定的账号范围映射，不能把“本地没有映射”理解成“DSH 没有会话”。

### 连接时序应成为程序状态

把“先退出、再打开、等准备好、再登录”的人工经验转化为可见状态和恢复入口。已有有效凭据应直接复用；确需用户登录时，再提示用户操作。
